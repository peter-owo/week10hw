# 簡報品質檢查規格

## 必要檢查

1. **來源覆蓋**：`raw/papers/`、`wiki/papers/`、`wiki/concepts/` 各有五個對應來源檔，連結存在。
2. **忠於 Wiki**：簡報第 2–7 頁的具體主張與 W1–W5 的事實 ID 一一對應；日期、數字、地域與起源措辭特別核對。
3. **簡報結構**：8–15 頁，先概念後例子，再有回顧與理解檢查。
4. **程式檢查**：所有本地 HTML 連結可找到，內嵌 JavaScript 語法正確，桌面渲染沒有明顯溢出。
5. **人工審查**：檢查讀者是否能回答「是什麼」「日期代表什麼」「習俗怎麼來」「是否各地相同」。

## Loop 決策

| 錯誤位置 | 返回節點 | 重做範圍 |
|---|---|---|
| 原始來源資訊不足 | 搜尋與 `raw/` | 該來源卡、閱讀筆記、概念與受影響簡報頁。 |
| 來源有但 Wiki 解讀過度 | `wiki/papers/` | 該筆記、概念與受影響簡報頁。 |
| 簡報與 Wiki 不一致 | `wiki/syntheses/` | 只重寫受影響簡報頁。 |
| 連結或畫面問題 | HTML | 只修介面與連結，不改事實。 |

每輪結果記於 [`qa-runs.md`](qa-runs.md)。通過所有必要檢查即可停止；最多修正三輪，仍有問題就明列限制。
